# G431 转动抖动根因：AS5600 掉进 100 ms 轮询的低功耗模式

日期：2026-10-27　板子：STM32G431CB + DRV8316C（云台 v1.1）+ AS5600（I2C 软件位翻转）
固件：`keil5_g431`，位置闭环，极对数 11 / 方向 -1 / 零点 1.697 rad

## 1. 结论先说

用户反馈的"转动时有明显抖动"、以及调试过程中反复出现的
"同一套增益有时稳有时不稳 / 速度怎么调都上不去 / 调参越调越差"，
**不是控制参数问题，而是位置反馈变成了 10 Hz**：

AS5600 会自己进入低功耗模式（CONF `0x07` 的 PMOD = 11，即 LPM3，**每 100 ms 才轮询一次**）。
在这个状态下角度寄存器每秒只刷新约 10 次。固件仍以 400 Hz 在做闭环，
于是每个控制周期里 39 拍的 `delta = 0`、第 40 拍突然跳 0.13 rad：

- 速度估计 `velocity = delta / dt` 变成"长时间为 0 + 一次 50 rad/s 的尖刺"，
  经 `MOTOR_VELOCITY_FILTER_TF = 0.02 s` 低通后是 5 rad/s 级的尖刺；
- 速度 PI（Vp 0.6 / Vi 5）把这些尖刺放大成饱和的 uq（长时间贴 2.5 V 限幅），
  形成 **10 Hz 极限环** —— 这就是手上感觉到的抖动；
- 位置环也因此跑不快，匀速只能到 ~1.3 rad/s（指令 1.5~6 rad/s 都一样）。

**只有把 AS5600 断电重启才能退出这个状态**；MCU 复位、重新烧录都不行
（传感器一直由 3.3 V 供电，不会跟着 MCU 复位）。这也是"早上好好的、下午同一套参数就抖"
的原因：期间某次供电波动把它带进了 LPM3，之后一直出不来。

## 2. 量化证据

### 2.1 编码器更新率（固件内计数器，SWD 读取 `as5600_stats[]`）

| 指标 | 卡在低功耗模式 | 断电重启后 |
| --- | --- | --- |
| 固件读取次数/s | 401.4 | 410.2 |
| **原始角度变化次数/s** | **10.1** | **393.6 ~ 408.8** |
| 相邻两次变化的最小间隔 | **97 ms** | **2.48 ms**（= 控制周期） |
| CONF `0x07` 回读 | `0xFF` → 写入后 `0xFC`（PMOD=11） | `0x00`（PMOD=00） |

### 2.2 闭环表现（host 侧 `tools/g431_jitter_probe.py cruise`，vlim 2.5 V）

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 匀速指令 1.5 rad/s 的实际速度 | −1.278 rad/s | **−1.5000 rad/s** |
| 角度抖动 std | 74.5 mrad | **8.8 mrad**（8.5 倍改善） |
| 角度抖动 p-p | 352.7 mrad | **44.2 mrad** |
| 速度噪声 std | 1.50 rad/s | **0.27 rad/s** |
| 主要谱峰 | 0.40 / **10.02** / 20.05 Hz（10 Hz 幅值 0.017） | 5.21 / 5.61 / 17.23 Hz（幅值 ≤0.004，10 Hz 峰消失） |
| 匀速指令 3.0 rad/s | −1.264 rad/s（顶到上限） | **−3.0001 rad/s** |
| 静止保持 uq | 频繁贴 2.5 V 饱和 | 0.3~0.8 V |

1 rad 位置阶跃（2.5 V）：0.25 s 到 24.9%，1.0 s 稳态误差 **0.0001 rad（0.006°）**，
速度收尾为 0，无过流、无跳闸。

## 3. 是如何定位的

1. 先用 SWD 读 `g431_diagnostics.loops` 确认控制循环本身是 400+ Hz（不是主循环被 CAN 拖慢）。
2. 用 host 侧高频轮询 `R` 抓原始报文，发现**相邻样本角度完全相等、每 2~3 个样本才跳一次
   0.10~0.14 rad**，且速度读数在两次跳变间单调衰减（说明 LPF 在 400 Hz 正常跑、delta 一直是 0）。
3. 在 `as5600.c` 加计数器 `as5600_stats[]`（更新次数 / 读取次数 / 最小最大更新间隔），
   SWD 直接读出 **updates/s = 10.1、min 间隔 97 ms**，排除主机侧与 CAN 的干扰。
4. 尝试写 `CONF` 把 PMOD 置 00：回读显示 `0xFC`（PMOD=0），但更新率仍 10 Hz
   → 说明**这个状态下写寄存器不能让它退出**。
5. 请用户给板子断电重启：`CONF` 回读变成 `0x00`、`updates/s` 变成 409、速度立刻跟得上指令
   → 根因确认。
6. 之后又空置 150 s 再测：`updates/s` 仍 393.6 → 新加的周期性 CONF 重写（每 1024 次读取）
   足以让它保持在正常工作模式。

## 4. 固件改动（`keil5_g431`）

- `BSP/as5600.c`
  - `force_normal_power_mode()`：读 `CONF(0x07)` 后**无条件**写回 `PMOD = 00`；
    `as5600_init()` 调用一次，运行中每 `AS5600_PMOD_REFRESH = 1024` 次读取重写一次（≈2.5 s）。
  - `as5600_stats[6]`：`[0]` 角度更新次数、`[1]` 读取次数、`[2]` 最后原始值、
    `[3]` 最小更新间隔 µs、`[4]` 最大更新间隔 µs、`[5]` CONF 回读；`as5600_conf_log` 记录修前/修后 CONF。
  - `as5600_ms_since_change()`：对外提供"距上次角度变化多少毫秒"。
- `BSP/board.h`：新增 `BOARD_STOP_SENSOR 16u`。
- `User/main.c`
  - **编码器停滞看门狗**：使能状态下若 `|motor.ramp_target - motor.angle| > 0.05 rad`
    且原始角度 120 ms 未变化 → `board_request_stop(BOARD_STOP_SENSOR)`，
    停机并打印 `FAULT encoder stale (AS5600 low-power mode? power-cycle the sensor)`。
  - 停机分支新增对应打印。
- 构建：`Code=22348 RO-data=1404 RW-data=124 ZI-data=3676`，0 Error 0 Warning。

## 5. 使用与排查提示

- **如果再次出现"转动抖动 / 速度上不去"，先给板子断一次电（5V/24V）再上电**，
  不要先动 PID。断电后恢复即说明是同一个问题。
- SWD 复测方法：

  ```powershell
  $nm = 'D:\program\STM32CubeCLT_1.21.0\GNU-tools-for-STM32\bin\arm-none-eabi-nm.exe'
  & $nm Objects\gimbal_g431.axf | Select-String 'as5600_stats|as5600_conf_log'
  # 然后 -r32 <addr> 24 读取；做两次、间隔 2 s，用 (updates 差)/(reads 差) 比较
  ```

  正常应为 `reads/s ≈ 400`、`updates/s ≈ 400`（转动时）；若 `updates/s ≈ 10` → 传感器又进了低功耗模式。
- host 侧量化工具：`tools/g431_jitter_probe.py cruise|step`，输出
  `speed / jitter_std_mrad / jitter_pp_mrad / vel_std / 谱峰`，作为"抖动有没有变好"的客观判据
  （修复前 74.5 mrad、修复后 8.8 mrad）。

## 6. 未解决 / 待观察

- **触发进入 LPM3 的确切原因未查明**（怀疑与供电波动有关：本板 DRV 内部 5V buck 已损坏，
  3.3 V 靠外部 5V + AMS1117 供）。现在的对策是"上电复位 + 周期重写 + 停滞看门狗"，
  不是从传感器侧根治。
- 周期性写 CONF 会在 ~2.5 s 时插入一次额外的 I2C 写事务，对 400 Hz 循环的影响未单独测量。
- `g431_jitter_probe.py step` 模式的 `peak_current` / `tail_err` 统计有 bug（出现 `nan` 与 49 rad
  的假值，原因是它从带缓存的 `?` 文本里取数），目前只信 `cruise` 模式的指标。
