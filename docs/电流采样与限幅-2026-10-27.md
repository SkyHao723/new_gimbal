# 相电流采样与电压限幅（G431 / DRV8316C）— 2026-10-27

用户目标：**"在保证电机不会烧坏的前提下，尽量拉高电压和电流的限制。"**
以前只有一个静态 `MOTOR_MAX_VOLTAGE`（5V，靠经验猜），现在改成"实测相电流 → 电压预算"，
并把 DRV8316C 片上 OCP 之外的保护做在固件里。

## 1. 结论先写

- 三路低侧相电流采样已经接进限流路径：TIM1 CH4 在"三相全低侧"窗口触发 ADC1 注入组，
  每 40µs 采一次三相电流；主循环据此折叠电压请求，中断里另有急停。
- 采样不可信时**必须**退化到 1.5V，不允许"看不见电流还开环加速"。
- 8V 硬上限是按采样窗口算出来的，不是拍的：请求 8V 时低侧窗口仍有 1540 counts（9µs），
  三通道转换只需要 1.76µs。
- 尚未在台架上验证。第一次上电必须先只读诊断，确认零点接近 2048 counts。

## 2. 硬件事实

原理图 `docs/hardware/g431-current-2026-10-20/page2-driver.png`：

| DRV8316CT 引脚 | 连接 | 影响 |
|---|---|---|
| pin40/39/38 SOA/SOB/SOC | PA0/PA1/PA2，**无 RC、无串阻** | 可短采样时间；采样点必须在低侧窗口 |
| pin31 GAIN / pin18 OCP-SR | 接 PGND | 电流检测增益 0.15V/A；OCP 固定档位 |
| pin37 VREF/ILIM | AVDD 3.3V | 满量程约 ±11A，零点约 VREF/2 ≈ 2048 counts |
| pin21 DRVOFF | 直接接 PGND | 硬件三相关断**不可用** |
| pin22 nSLEEP | PB0 | 唯一的硬件断电手段 |
| pin33 nFAULT | PB2，1K 上拉 | 低有效，EXTI2 下降沿急停 |

由此得出两个改造点：① 关断必须 `清 MOE + 拉低 nSLEEP(PB0)`，只清 MOE 是低侧全通刹车；
② 电流采样在低侧导通窗口才有效，所以触发点必须跟着占空比走，不能固定。

## 3. 固件结构

```
foc_svpwm → duty[3] ──> board_pwm()
                          ├─ CCR1..3 = duty*ARR
                          ├─ CCR4 = max(CCR1..3) + 160   ← 采样触发点
                          └─ pwm_low_window = 2*(ARR-maxCCR) - 160
TIM1 OC4REF 上升沿 → ADC1 注入组 IN1/IN2/IN3 → ADC1_2_IRQHandler
                          ├─ 换算 amp[3] = (raw-offset)*0.005371 A/count
                          ├─ peak / mean-square / 样本计数
                          ├─ >2.6A 连续两次或 >4.5A 一次 → board_request_stop(CURRENT)
                          └─ 更新 s_last_sample_us
主循环 → current_limit_update() → allowed_v
       → motor.voltage_limit = min(requested, allowed, 8V) → motor_step()
```

- `BSP/current_sense.{c,h}`：ADC/TIM1 触发配置、静止零点标定、中断内换算与急停。
- `User/current_limit.{c,h}`：纯逻辑（不依赖 STM32 头），可在主机上跑单元测试。
- 共享的 `keil5_foc/Control/motor.c` **没有改**，避免影响已验证的 F103 基线；
  电流监督直接写 `motor.voltage_limit` 这个公开字段。

## 4. ADC / TIM1 配置要点

| 项目 | 取值 | 理由 |
|---|---|---|
| ADC12 内核时钟 | PLLP 170MHz ÷ `ADC_CCR_PRESC=4` = 42.5MHz | `RCC_CCIPR.ADC12SEL=01`；G4 没有 HSI16 选项；上限 60MHz |
| 采样时间 | SMP=2 → 12.5 周期 | 引脚无 RC，不需要长采样 |
| 每通道 / 三通道 | 25 周期 1.5625µs / 75 周期 1.76µs | |
| 注入组 | JL=2，IN1/IN2/IN3 = PA0/PA1/PA2 | |
| 触发源 | `JEXTSEL=1`=TIM1_CC4，`JEXTEN=1` 上升沿 | F1/G4 的 CC4 不能触发 ADC？G4 可以 |
| JADSTART | 只在标定时写一次，之后不 JADSTOP | 持续采样，避免每周期重新启动 |
| 中断 | `ADC1_2_IRQHandler`，优先级 1 | 低于 nFAULT(0)，高于 FDCAN(1 同级) |
| 窗口需求 | `ARR-CCR4 >= 300 counts` | 主循环用 `board_pwm_low_window()` 复核 |

`CCR4 > ARR` 时永不触发，等价于"采样停摆"。主循环 5ms 收不到新样本 → `blind`
→ 电压压到 1.5V；1.5V 下占空比偏移只有 0.047，窗口自动恢复到 2922 counts，采样重新
开始，限幅器随即解除 blind。这个回环是刻意的自恢复设计。

## 5. 保护层级

| 层 | 位置 | 阈值 | 动作 |
|---|---|---|---|
| 1 | ADC 中断 | 峰值 > 4.5A 一次 | 立即 `board_request_stop`，不等主循环 |
| 2 | ADC 中断 | 峰值 > 2.6A 连续两次 | 同上（滤掉单次噪声） |
| 3 | 主循环限幅 | 峰值 > 1.6A | `allowed -= (peak-1.6)*10 V/A`，线性折叠 |
| 4 | 主循环 I²t | `msq > 1.4A(RMS)²` | `allowed *= (1-thermal)`，8s 时间常数，clamp[0,1] |
| 5 | 主循环锁存 | 峰值 ≥ 2.6A | `tripped` → 请求停机并打印 `FAULT overcurrent` |
| 6 | 硬件 | nFAULT 下降沿 / 过流 | EXTI2 优先级 0，`driver_off()` |
| 7 | 硬上限 | 任何路径 | `motor.voltage_limit` 永不超 `MOTOR_MAX_VOLTAGE`(8V) |

`mean_square` 是三相电流的均方再除 3。正弦驱动时三相平方和 = 1.5·I_peak²，
除 3 得 0.5·I_peak²，所以 `msq == rated²` 恰好对应 I_RMS = rated = 1.4A。
I²t 的物理含义因此是"额定电流定义为有效值"。

## 6. 参数（`User/motor_config.h`）

| 宏 | 值 | 含义 |
|---|---|---|
| `MOTOR_VOLTAGE_LIMIT` | 4.0V | 上电默认 `V` 请求 |
| `MOTOR_MAX_VOLTAGE` | 8.0V | 硬上限，`V` 命令也只能到这儿 |
| `CURRENT_LIMIT_RATED_A` | 1.4A | 连续相电流（有效值） |
| `CURRENT_LIMIT_SOFT_A` | 1.6A | 开始折叠 |
| `CURRENT_LIMIT_TRIP_A` | 2.6A | 请求停机 |
| `CURRENT_LIMIT_FOLD_V_PER_A` | 10 V/A | 折叠斜率 |
| `CURRENT_LIMIT_VOLTAGE_FLOOR` | 1.5V | 失明时的唯一允许值（也是折叠下限） |
| `CURRENT_LIMIT_PEAK_DECAY_S` | 0.05s | 峰值线性释放时间常数 |
| `CURRENT_LIMIT_THERMAL_TAU_S` | 8s | 绕组热时间常数（粗估） |
| `CS_GAIN_V_PER_A` | 0.15 | DRV8316C GAIN=PGND |
| `CS_AMP_PER_COUNT` | 0.005371 | 3.3/4096/0.15 |

电流模型是 `I = (raw - offset) × 0.005371 A/count`；offset 每次上电静止标定，
不写死 2048，因为 VREF 和运放偏置有分散性。

## 7. 台架首次验证（务必按顺序）

```powershell
# 0) 只读诊断，固件默认失能，不会转
python tools/g431_probe.py --samples 3
```

判据：

1. `stage=4`，`core_clock=170000000`，`enabled=0`，`off_high=1`，`sleep_high=1`。
2. `cs_valid=1`；`cs_samples` 三次采样之间增长约 2500（0.1s × 25kHz）；
   `cs_peak` 接近 0（|peak| < 0.3A）；`cs_blind=0`；`cs_trips=0`。
3. `?` 的 `I` 行：`I pk=0.0xA allowed=8.00V req=4.00V th=0.00 smp=... trips=0 ok=1`。

异常判读：

| 现象 | 含义 | 处理 |
|---|---|---|
| `cs_valid=0` 且 `cs_blind=1` | 零点标定失败：SOx 不在 10%~90% 满量程 | 见下一条；先确认 24V 已上、DRV 已唤醒 |
| 三个 offset 都 ≈ 0 | SOx 可能是单向输出（不是 VREF/2 偏置） | 把零点模型改为 0 并重算 `CS_AMP_PER_COUNT`，再验增益 |
| `cs_valid=1` 但 `cs_samples` 不涨 | CC4 触发没生效 | 查 `CCR4`、`CCER.CC4E`、`CCMR2.OC4M=7`、`JEXTN/JEXTSEL` |
| `cs_ok=0` 且电压被压到 1.5V | 采样停摆或窗口不足 | 正常退化，先修采样再看电压 |

采样确认可信后，才用 CAN 工具发 `E` 和小目标角，先看 `I pk=` 是否随负载变化，
再手动短时堵转验证折叠和 `FAULT overcurrent`，最后才讨论把 `V` 提到 8V。

## 8. 未验证 / 风险

- **零点位置未实测**。满量程 ±11A 是根据 GAIN=0.15V/A、VREF=3.3V 推的，未经台架确认。
- DRV8316C 的 SOx 在 nSLEEP 拉低后输出无效；停机和重新使能瞬间的读数会被限幅器忽略
  （`enabled=0` 时 peak 归零、MOE=0 时中断不判跳闸），但这段时序只在推理层面检查过。
- 1.4A 额定、8s 热时间常数来自电机参数表，没有热模型标定。
- 电压上限 8V 只保证"采样窗口够用"，不保证电机机械/热上能长期吃 8V；
  真正的约束仍是限幅器算出的 `allowed`。
- 采样点位于低侧窗口起点后 0.94µs，未用示波器确认开关噪声不影响读数。

## 硬件验证：折叠与跳闸实测（2026-10-27 晚，CAN 接通后）

为了证明限流链路真的会动（而不是只写了代码），把阈值临时压低后跑连续运动：

- `CURRENT_LIMIT_SOFT_A` 0.120 A、`CURRENT_LIMIT_TRIP_A` 0.300 A，其余不变，电压上限 8 V，
  CAN 下发 ±1.2 rad 摆动（1 s/次）。实测 `allowed` 随峰值电流线性下降，与设计公式
  `allowed = ceiling - (peak - soft) * fold`（fold = 10 V/A）逐点吻合：

  | 峰值电流 | 实测 allowed | 公式值 |
  | --- | --- | --- |
  | 0.160 A | 7.59 V | 7.60 V |
  | 0.180 A | 7.39 V | 7.40 V |
  | 0.190 A | 7.30 V | 7.30 V |
  | ≤0.120 A | 8.00 V | 8.00 V |

- 加大摆幅、缩短周期后峰值冲到 **0.310 A > trip 0.300 A** → 电机立即失能，随后的状态读回：
  `EN=OFF angle=-5.2263 vel=0`，三相电流全部归零，角度冻结，后续 `T` 命令不再执行。
  即**循环级过流跳闸在硬件上生效**。
- 恢复 `soft 1.6 A / trip 2.6 A` 重新烧录后：`allowed=8.00V`、`ok=1`、`trips=0`，一切正常。

未在硬件上验证的部分：**ADC 中断级兜底（连续两次 >2.6 A 或单次 >4.5 A）**。要触发它需要真正
堵转（机械抱死），风险比收益大，因此保持"仅代码审查 + 主机单测"的验证等级。需要时可以用上面同样的
办法把 `CS_ISR_TRIP_A` 临时压到 0.4 A 来验证。
