# 闭环 FOC 实施规划

> 目标：在 **测试版**（STM32F103C8T6 + SimpleFOC Mini/DRV8316C + AS5600）上打通闭环
> 原则：**安全性优先**，每一步独立可验证，任何一步失败都能安全回退
> 基线：固件 `mini_test.c`（六步换相）已实测通过，作为**永远可回退的安全版本**

---

## 一、现状与阻塞点

### 已完成（有实测依据）

| 能力 | 验证方式 |
|---|---|
| PWM TIM1/PA8-9-10，25kHz 中心对齐 | 寄存器 `BDTR=0x8000`、`CCER=0x111`、`ARR=1439` + 万用表实测 |
| 六步换相旋转 | 空载电流 < 0.1 A（标称 0.1 A） |
| 电流采样 + 零点标定 | 漂移 ±0.005 A；1V→0.142A / 2V→0.317A，反推电阻 6.5Ω |
| 过流硬切断 | 自检通过（阈值降到 0.05A 未误触发） |
| 72MHz 时钟 | `SystemCoreClock=72000000` |

### 唯一阻塞点：编码器在控制循环中的可靠性

**现象**
- 调试固件里，`Motor_init()` 帧内读 `getAngle()` 正常
- 但在**控制主循环**中长期运行后，读数失败 → `I2C_getRawCount()` 返回 0 → `shaftAngle` 变 **NaN**
- 慢速调 `angle=nan` 反复出现

**根因分析（三个叠加因素）**

1. **I2C 驱动本身脆弱** — 原参考工程用「POS 位技巧 + 直接寄存器操作」，且所有超时路径 `return 0` **不发 STOP**，一次失败就把 SCL 拉死（已修，但未在闭环中验证）
2. **400kHz 在排线上太快** — 信号完整性差，读十次错两三次
3. **无数据有效性检查** — 脏数据（0 / NaN）直接被 FOC 拿去算换相角

**危害等级：高**
编码器脏数据 → 换相角错误 → 电机失步 → 等效堵转 → 大电流（与 145W 事故同一机制）

### 设计原则

> **编码器不可信，就绝不能开闭环。**
> 因为开环至少是"我知道它在转"，闭环脏数据是"它在乱转还可能烧电机"。

### 阶段 1 — 编码器可靠性攻坚（★ 最高优先级，1~2 天）

**目标**：AS5600 在**控制循环频率下**（≥ 1kHz 读取）长期稳定，错误率 < 0.1%

**为什么单独作为一个阶段**
这是唯一的阻塞点，且解决它需要独立的测试装置。不掺任何电机控制代码，
纯粹验证"读角度"这一件事。

**任务**

1. **重写 I2C 读角度驱动**（不复用原参考代码）
   - 速率降到 **100 kHz**
   - 标准两步读（不用 POS 位技巧，简单优先）
   - 每个超时点：发 STOP + 清 POS + 恢复 ACK
   - 加**总线恢复**：卡死时用 SCL 脉冲解救从机
   - 读失败时返回一个**明确无效标志**，而不是 0

2. **数据有效性校验**
   - 连续两次读，差值 < 阈值才接受
   - 与上一次比，跳变 > 某阈值 → 判为野值丢弃
   - 累计失败计数器（可读）

3. **独立测试装置**（新固件 `encoder_test.c`，不接电机）
   - `R` 连续读取 N 次，打印失败次数与角度抖动
   - 静态：读数应稳定（抖 < 2 LSB）
   - 手动转轴：角度应单调变化
   - **持续 10 分钟压力测试**

**验收标准**

| 指标 | 要求 |
|---|---|
| 静态角度抖动 | < 2 LSB (4096) |
| 手动连续转动 | 角度单调、无跳变 |
| 10000 次读取失败率 | **< 0.1%** |
| 失败后能否自愈 | 下一次读必须成功（不能卡死） |
| 10 分钟长跑 | 无累积性失败 |

**停止条件**（任一出现则暂停，换方案）

- 错误率 > 1% 且降速/加滤波无效
- 总线反复卡死，恢复机制不能自愈

**备选方案（按优先级）**

1. 降到 100 kHz + 缩短排线 + 检查上拉（**首选，最可能直接解决**）
2. 增加"读两次取一致"的双读冗余（软件容错）
3. 改用 AS5600 的 **PWM 输出**（单线，抗干扰远好于 I2C，引脚 PA0/PA1/PB1 已有）
4. 换成 SPI 编码器（MT6701，厂家也有资料）

> ⚠️ 注意：仓库 `reference/` 里有厂家给的其他方案（ESP32 + MT6701 等），
> 如果 AS5600 实在不稳，换编码器比死磕 I2C 更划算。

**产出**：`app/encoder.c/.h` —— 一个经过验证的、可信的角度读取模块

#### 阶段 1 实测结果（✅ 已通过）

**测试时间**：2026-10-15　**固件**：`app/encoder_test.c`（不输出 PWM，EN 保持失能）

| 测试项 | 结果 | 判定 |
|---|---|---|
| SCL/SDA 空闲电平 | 均为 HIGH | ✅ 上拉有效 |
| 静止抖动（1000 次） | 跨度 **1 LSB** | ✅ 要求 < 5 LSB |
| **400 kHz 抖动（500 次）** | 0 / 1000 失败 | ✅ 400kHz 也能用 |
| **100 kHz 抖动（1000 次）** | 0 / 2000 失败 | ✅ |
| **压力测试 20000 次** | **0 / 40000 失败，错误率 0.0000%** | ✅ **要求 < 0.1%** |
| abort（超时清理） | **0 次** | ✅ 从未超时 |
| recover（总线恢复） | **0 次** | ✅ 从未卡死 |

**重大发现：原判断错误修正**

我原先怀疑"400 kHz 在排线上信号完整性差"，**这是错的**。
实测 **400 kHz 同样 0 失败**。

真正的根因是：**原驱动在所有超时路径直接 `return 0`，不发 STOP → 一次失败就把总线永久拉死**。
一旦卡死，之后每次读都失败，`angle` 就恒为 0 / NaN。

**修复三要素**（`app/encoder.c`）
1. 每个等待点都有有限超时，超时后**必发 STOP**释放总线
2. 失败返回**明确错误码**，绝不返回 0 冒充有效角度
3. 数据校验：双读一致性 + 跳变丢弃 + 统计（abort/recover/outlier）

**仍有待关注的问题：磁场偏弱**

```
STATUS=0x33  AGC=128  MAGNITUDE=909
  MD=1（检测到磁铁）  ML=1（磁场太弱❗）  MH=0
```

`ML=1` 且 `AGC=128`（正常应接近 0）说明**磁铁与芯片间距偏远**。
虽然角度读数稳定，但弱磁场可能导致**角度非线性/精度下降**，
影响 FOC 换相质量。**建议在进入阶段 3 对齐前先处理**：

- 把磁铁往芯片方向靠近（目标 AGC 降到 0~50，ML 清零）
- 或确认厂家预装磁铁是否松动/错位

### 阶段 3 — 对齐（★ 最危险的一步，1 天）

**目标**：让 `alignSensor()` 成功，得到 `sensor_direction` 与 `zero_electric_angle`

**为什么危险**
对齐会强制电机做开环旋转，且**在闭环代码路径里**。参数不对会让电流失控。

**任务**

1. **对齐参数收紧**
   - 对齐电压：从 **1.5 V** 起步（对应约 0.23 A），不够再逐步加
   - 必须 < `voltage_limit`
   - 限制对齐过程的总转角和持续时间

2. **每个对齐步内插入过流检查**
   ```
   for 每一步:
       setPhaseVoltage(align_v, angle)
       读电流 → 超限立即 EN 拉低 + 中止
       延时
   ```
   > 原库的 `alignSensor()` 内部是 `delay_ms(2)`，**没有电流检查**，
   > 必须在循环体里插入。

3. **分步观察**
   - 先只跑"前 500 步正转"，打印 mid/end 角度，确认能测到运动
   - 再跑完整对齐

4. **结果校验**
   - `sensor_direction` 必须是 ±1，不能是 0
   - `zero_electric_angle` 应落在 [0, 2π]
   - `PP check: OK!` 或打印出建议极对数

**验收**
- `sensor_direction = CW 或 CCW`（非 0）
- `zero_electric_angle` 是有限值
- 极对数校验通过（或按提示改正后通过）
- **全程最大电流 < 1.5 A**

**停止条件**
- 反复 `Failed to notice movement` → 编码器又不可信了，**回到阶段 1**
- 对齐时电流异常 → 立即停，检查对齐电压与电机接线

**产出**：对齐参数字典（记录成功的电压、耗时、方向、零点）

### 阶段 4 — 闭环三模式逐步验证（1~2 天）

**目标**：力矩 → 速度 → 位置，逐个跑通

#### 4.1 力矩模式（最先做，最好观察）

**为什么先做**：给固定电角度 → 转子锁在固定位置 → **不动 = 不会失步 = 最安全**

- 任务：给固定 `Uq`（从 1V 起）和固定电角度，观察转子是否锁住、电流是否与 `V/6.5` 吻合
- 验收：转子锁定不抖；电流符合 `I ≈ V/6.5`；松开后能保持位置
- 安全：`Uq` ≤ 2V，超流立即断

#### 4.2 速度模式

- 任务：从**很小的目标**开始（`T1` = 1 rad/s），PID 先给保守值
- 观察：响应方向对不对、有没有振荡、`shaft_velocity` 是否跟随
- 验收：能稳定跟随给定；无发散；**电流 < 1.4 A 额定**
- 安全：`velocity_limit` 先设小（如 10 rad/s）；目标值逐步加

#### 4.3 位置模式（最后做）

- 任务：给定阶跃目标，观察是否到位、有无过冲/振荡
- 验收：稳态误差可接受；无持续振荡；阶跃响应可重复
- 安全：阶跃幅度先小（±0.5 rad）

**PID 调参原则（安全第一）**
```
先 P 小、I=0、D=0  → 慢慢加 P 到刚好有响应
再加 I 消除稳态误差（注意积分饱和 → 库里有 antiwindup）
最后加 D 抑制过冲
每个参数只改一个，且每次改完先看电流
```

**产出**：三套可用的 PID 参数 + 每种模式的测试记录

## 七、与正式版（G431）的关系

测试版跑通后，正式版需要改的：

| 项目 | F103（测试版） | G431（正式版） |
|---|---|---|
| PWM | TIM1 CH1/2/3，PA8/9/10 | TIM1 CH1/2/3（**同一个定时器，改引脚**） |
| 时钟 | HSE 8MHz × 9 = 72MHz | HSE 8MHz + PLL → 170MHz |
| 电流采样 | ADC1 规则组 + DMA | **ADC1 注入组 + TIM1 触发**（更准） |
| FOC 库 | SimpleFOC 移植版 | 建议直接用官方 SimpleFOC 的 STM32G4 支持 |
| 编码器 | I2C1 (AS5600) | I2C1 或 SPI（MT6701） |

**所以测试版把闭环逻辑跑通，正式版主要是"换平台 + 换引脚"，算法层可复用。**
