## 一、修复 1：串口命令丢包 —— 已验证解决 ✅

### 根因

Arduino STM32 core 的串口命名与直觉**完全不同**：

```c
// cores/arduino/Serial.cpp
Uart Serial1(USART1);   // ← Serial1 是 USART1 (PA9/PA10)
Uart Serial2(USART2);   // ← Serial2 才是 USART2 (PA2/PA3)
```

**PA9/PA10 已被 PWM 占用**，所以之前用 `Serial1` 想接 USART2，
实际去操作 USART1 —— 等于用一个引脚被 PWM 抢走的串口收发，命令丢一半。

### 修复

`platformio.ini`：
```ini
build_flags =
    -O2
    -ffunction-sections
    -fdata-sections
    -Wall
    ; ---- 串口：启用 Serial2 = USART2 (PA2/PA3) ----
    -D HAVE_HWSERIAL2
    -D PIN_SERIAL2_TX=PA2
    -D PIN_SERIAL2_RX=PA3
```

`main.cpp`：把手写串口换成核心的 **`Serial2`**。

**注意**：不要定义 `HAVE_HWSERIAL1`，否则 `Serial1` 会去抢 PA9/PA10（PWM 引脚）。

### 实测结果（`test/serial.ps1`）

```
TEST 1 (20x R):                  20/20  OK
TEST 2 (20x ?):                  20/20  OK
TEST 3 (突发 10x R, 无延时):      10/10  OK

TEST 4: 参数命令真的生效
  set V2.5    -> status Vlim=2.50        ✅
  set V3      -> status Vlim=3.00        ✅
  set T1.234  -> target=1.2340, tgt=1.2340 ✅

RESULT: SERIAL FIX CONFIRMED - 100% reliable
```

**顺带收益**：Flash 占用从 83.9% 降到 **63.3%**（删掉手写串口代码）。

## 二、修复 2：对齐失败导致电机完全不动 —— 已验证解决 ✅

### 现象

```
aligned: dir=CCW
         zero_electric_angle=-12345.0000     ← NOT_SET 哨兵值
...
T5.3545  moved=0.0000  expected=0.30        ← 完全不动
```

`dir=0`(UNKNOWN) + `zero_electric_angle=-12345`(NOT_SET) 说明
**`initFOC()` 里的 `alignSensor()` 失败了** → FOC 不知道电角度零点
→ 交给驱动的电压相位是错的 → 电机不动。

### 根因

**对齐电压只有 1.0V，推不动转子。**

SimpleFOC 的对齐流程需要让转子**转一整圈**来测传感器方向：

```c
// BLDCMotor::alignSensor()
// 正转 500 步、反转 500 步，比较 mid_angle / end_angle 得出 sensor_direction
```

1.0V 正是前面实测"力矩不足、完全不动"的电压 —— 转子不转，
方向检测自然失败。

### 修复

```c
#define ALIGN_VOLTAGE   3.0f      /* 从 1.0f 提到 3.0f */
```

**原则：对齐电压必须 >= 能可靠推动转子的电压。**

### 实测结果

```
对齐前:  aligned: dir=CCW   zero_electric_angle=-12345.0000    ❌
对齐后:  aligned: dir=CW    zero_electric_angle=2.8256          ✅
```

## 三、闭环控制的真实状态

### 能工作的部分 ✅

```
>>> ENABLE (base=7.0072)
    angle after enable = 6.9919

--- 小步移动 (0.2 rad)，每步保持 1.5s ---
  step 1: moved=0.2009  err=-0.0009      ← 误差 0.09%
  step 2: moved=0.2010  err=-0.0010      ← 误差 0.10%
  step 3: moved=0.2101  err=-0.0101      ← 误差 0.48%

--- 静止保持测试 3 秒 ---
  drift over 3s = 0.0000 rad             ← 完全无漂移 ✅
```

**小幅度移动精度极高（误差 < 0.5%），静止时完全稳定。**

### 不工作的部分 ❌

累积移动超过约 **0.6 rad** 后失稳：

```
  step 4: moved=0.9388  err=-0.7388      ← 乱甩（期望 0.2）
  step 5: moved=-0.7547 err=0.9547       ← 反向乱甩
```

### 根因分析

**速度环被编码器噪声污染。**

实测证据：电机静止时 `vel` 会乱跳：

```
EN=OFF  angle=4.844  vel=0.963
EN=OFF  angle=4.844  vel=2.726     ← 角度完全相同，速度却差 3 倍
EN=OFF  angle=4.844  vel=0.686
```

原因：AS5600 是 12 位（4096 线），`vel` 由角度差分得到。
角度只有 ±1 LSB 噪声时，差分测速会把噪声放大成 **2.7 rad/s 的假速度**。

速度环把这个假速度当成真实反馈 → 输出错误的电压 → 运动时失稳。
静止时不失稳是因为位置环的 P 增益把转子压住了。

### 下一步建议（交给接手 AI）

按优先级尝试：

| 参数 | 当前值 | 建议方向 | 原因 |
|---|---|---|---|
| `LPF_velocity.Tf` | 0.01 | 加大到 0.05~0.1 | 更强的滤波压掉速度噪声 |
| `PID_velocity.P` | 0.2 | 降到 0.05~0.1 | 降低速度环对噪声的敏感度 |
| `PID_velocity.I` | 20 | 降到 5~10 | 同上 |
| `P_angle.P` | 20 | 降到 8~12 | 减小速度指令的突变 |
| `V_LIMIT` | 3.0V | 试 4.0V | 力矩裕度更大，抗扰动更强 |

**调试方法**：用 `test/closedloop.ps1` 反复跑，看 `moved` vs `expected`
的偏差是否稳定。**每次只改一个参数。**

### 另外可考虑的方向

- **启用电流采样**：驱动板有 CS1/CS2/CS3 输出（接 PA0/PA1/PB1），
  改用 `TorqueControlType::foc_current` 可绕开速度环噪声问题
- **检查速度观测器**：SimpleFOC 的 `LPF_velocity` 是简单一阶低通，
  可以考虑换更平滑的测速方法
