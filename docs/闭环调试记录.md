## 一、本阶段确认的事实

### ✅ 已验证可用

| 项目 | 证据 |
|---|---|
| **编码器（AS5600）** | 40000 次读取零失败；手动转轴 raw 从 316 变到 3885，累计 11 rad |
| **编码器标定** | 反复标定结果一致：`mech≈-0.64 rad`, `offset≈-4.49`, `raw≈3679` |
| **电机能转（六步开环）** | 角度从 -2.19 持续变到 -1.47，电流稳定 0.15A |
| **电流采样（小电流）** | Z 测试：0.5V→0.049A、1.0V→0.138A、1.5V→0.224A，与 6.5Ω 吻合 |
| **过流保护** | 多次正确动作，立即拉低 EN |
| **TIM1 三路 PWM** | `BDTR=0x8000`、`CCER=0x111`、`ARR=1439` |
| **72MHz 时钟** | `SysClock=72000000` |

### ❌ 受阻：闭环无法起转

**现象**：闭环下施加电压但转子不动，编码器读数恒定（`mech=-0.6397` 不变），
电流只有 0.02~0.25A（远低于预期），电角度恒为常数。

**根因（已分析清楚）—— 起动"死点"**

标定过程把转子锁在电角度 = 0 的位置，此时：

```
力矩 T ∝ sin(θ_field - θ_rotor) = sin(0) = 0
```

**无论给多大电压都不产生力矩**。而闭环的换相角来自编码器，
转子不动 → 编码器不变 → 电角度不变 → 磁场静止 → 始终 sin(0)=0。

这是一个**自锁死循环**。

**已尝试的修复**：加 90° 电角度偏离（sin(90°)=1 力矩最大），
但受限于命令解析时序问题（见下），尚未取得有效测试结果。

## 二、调试中踩到的坑（重要经验）

### 1. 测量 I2C 引脚电平前必须先 `PE=0`

**错误做法**：直接在 I2C 外设开启时读引脚 → 读到的是外设拽住的状态
→ 误判为"SDA 对地短路 / 芯片损坏"。

**正确做法**：先 `I2C1->CR1 &= ~PE`，等外设释放引脚，再切成上拉输入测量。

### 2. I2C 外设会进入异常状态，每次读失败都要主动恢复

修复要点（已写入 `app/encoder.c`）：
- 恢复序列第一步必须是 `PE=0`
- `encoder_read()` **任何失败都调用一次恢复**（不只是从机不应答时）
- 恢复延时不能太长（原本 20000 次循环 ≈ 0.5s，导致看起来像卡死）

### 3. 用轮询时绝对不能开 `RXNEIE`

**症状**：启动信息正常打印，但所有命令无响应。

**原因**：`uart_init()` 里开了 `RXNEIE` + NVIC，但命令接收改成了轮询。
轮询读走数据后从不响应中断 → **RXNE 中断无限触发** → 主循环永远得不到执行。

**正确做法**：轮询就纯轮询，`USART2->CR1 = 0x200C`（UE|TE|RE，无中断）。

### 4. 编译器会把"读标志位"的循环优化成死循环

**症状**：主循环卡死，串口无响应。

**反汇编证据**：
```
800189c:  ldrh  r3, [r2, #0]     ← 只读一次
800189e:  lsls  r3, r3, #16
80018a0:  bpl.n 800189c          ← 跳回【自己】，永远用同一个值
```

**修复**：用 `volatile` 变量 + 函数封装强制每次重新读内存：
```
8001928:  ldrh r3, [r2, #0]      ← 跳回【读取】而不是自己 ✅
800192a:  uxth r3, r3
800192c:  strh r3, [sp, #92]
8001930:  ldrh r3, [sp, #92]
8001934:  lsls r3, r3, #16
8001936:  bpl.n 8001928
```

### 5. 命令解析的时序坑

固件在收到 `\r` 时就处理命令。如果连续快速发送，后面的字符会来不及进缓冲区：

```
发送 "V2\r\n" 太快 → 固件只看到 'V' → Vlim 被解析成 0.00
```

**对策**：发命令间隔 ≥ 500ms。

### 6. 看门狗在调试阶段有害

IWDG 导致固件卡死时不断复位 → **ST-Link 都连不上**（DEV_CONNECT_ERR）。
调试期建议关闭，产品阶段再启用。恢复方法：**断电重启**。

### 7. 电流零点在 EN 使能前后不同

实测：EN 关时 raw≈1759，EN 开时 raw≈2064，**差 305 counts ≈ 0.83A**。
必须分别标定两套零点，按 EN 状态选用（已实现 `adc_zero_on/off`）。

## 三、仍待解决

### 主要问题：闭环起动

**可行方向（按优先级）**

1. **开环起动 + 闭环运行**（最标准、最可靠）
   - 前 0.5~1 秒用**独立于编码器**的开环磁场把转子带起来（转速 2~5 rad/s）
   - 确认编码器出现速度（`|vel| > 0.5`）后，切换到闭环
   - 这是所有 FOC 驱动器的标准做法

2. **加大起动电压**
   - 当前 2~3V 上限可能不足以克服静摩擦
   - 但需先解决电流采样在大电流下的可信度问题

3. **改用六步换相闭环**（已实现，但同样受死点影响）
   - 六步换相在开环下已证明能转（角度持续变化）
   - 加上编码器决定换相时机的闭环尚未成功

### 次要问题：电流采样可信度

电压扫描测试显示读数不稳定（反推电阻在 2.5~141Ω 间跳变）。

**建议**：用**外部电流表**（钳形表或电源显示的电流）做一次标定，
核对 `A_per_cnt` 系数是否准确。当前用的是假设值 0.00269（对应 0.3V/A 增益）。
