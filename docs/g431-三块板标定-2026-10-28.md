# G431 三块板：每块板零点的实测标定（2026-10-28）

## 结论先写

1. **每块板的 `zero` / `dir` 必须单独实测，不能互相抄。** 三块板用的是同一型号电机、
   同一种驱动板，但磁铁环是手工粘在转子上的、三相线也能任意插，所以电气零点和
   传感器方向都不一样：

   | 节点 | 极对数 | 方向 | 零点 (rad) | 零点拟合残差 |
   |---|---|---|---|---|
   | node1（板 1） | 11 | −1 | 1.227 | 4.7° rms / 8.1° max |
   | node2（板 2） | 11 | −1 | 0.122 | 5.1° rms / 8.6° max |
   | node3（板 3） | 11 | **+1** | 0.487 | 3.7° rms / 7.4° max |

2. **方向写错时的现象不是"抖"，而是"完全不动 + 大电流发烫"。** 板 2 曾沿用板 3 的
   `dir=+1`，电压矢量正好压在转子磁极轴线上（d 轴）：实测 `uq` 顶到 2.5 V 限幅、
   `pk` 1.07 A，转子一步不动——电流全部变成铜损。这种状态下继续跑就是拿电机当
   电炉，所以固件里的"编码器停滞看门狗"其实救了它一命。
3. **单次拉轴的零点精度只有几十度电角**（磁滞+齿槽），改用"双向拉轴 + 平均"后
   残差降到 ~5°（`cos 5° = 0.996`，转矩损失 0.4%）。工具链已固化：
   固件双拉 + `tools/g431_fit_align.py` 拟合。

## 板 2 的完整排查链（为什么不是功率级）

| 检查 | 结果 | 结论 |
|---|---|---|
| 补焊前 DC 锁相（0.6 V 差压） | 三相电流 1–4 mA | 功率级确实坏了 |
| 补焊后 DC 锁相 | ±0.08 A、三相对称、基尔霍夫闭合、`worst=0.186 A` | 功率级恢复 |
| 补焊后 CSA 偏置 | 2044/2044/2045 counts ≈ 1.65 V（之前 730） | 采样链路恢复 |
| 开环转动（0.8 V / 1 Hz / 4 s） | 位移 +4.05 rad、`worst=0.364 A` | 驱动与机械正常 |
| MCU 侧寄存器 | `BDTR=0x8000`(MOE)、`CCR1/2/3` 非对称、PA8/9/10=AF | 不是 MCU 问题 |
| 闭环发 T（沿用板 3 标定） | 角度冻结、`uq=2.5 V`、`pk=1.07 A` | **矢量压在 d 轴：方向错** |
| 改 `dir=-1` 后闭环 | 1 rad 阶跃误差 0.0001 rad、`pk=0.05 A` | 正常 |

补充：`EXTI2`（nFAULT 下降沿）在"关闭驱动 → 下一次使能"之间会被 latch 触发一次，
连续跑多行标定时会表现为下一行 `board_driver_set(1)` 直接返回失败（结果码 −2）。
`bench_align_run()` 现在对使能做了 5 次重试，这个竞争就不会再让整轮标定白跑。

## 双向拉轴标定法

单个 d 轴矢量把转子拉向目标，但摩擦力/齿槽让转子**停在目标之前**，偏差方向取决于
从哪一侧靠过来。

固件（`User/bench_current.c` 的 `bench_align_run()`）现在每行做两次：

1. 磁场先停在 `theta − BENCH_ALIGN_SWING`（0.9 rad 电角），再在 `hold_ms/4` 内
   平滑扫到 `theta`，保持 `hold_ms/2`，取最后 200 ms 的机械角 → 存入 `[1]`；
2. 磁场先停在 `theta + BENCH_ALIGN_SWING`，同样扫到 `theta` → 存入 `[6]`。

两次测量跨在真值两侧，离线拟合时把它们当作两个观测一起做圆周平均，磁滞被抵消。

拟合判据：对每个候选 `(pp, dir)`，把每行的 `(dir·pp·m − theta)` 归一化到
`(−π, π]`，取圆周均值，再看所有行/两次测量的最大偏差。偏差最小的组合就是答案；
同时"残差"本身也是质量指标（应 ≲ 6°）。

## 复现步骤

```powershell
# 1) 打开标定测试（User/motor_config.h）
#    #define G431_ALIGN_TEST  1        （其余四个 bench 宏保持 0）
# 2) 编译 + 烧录对应节点
& powershell -ExecutionPolicy Bypass -File build\g431_build_nodes.ps1 -Nodes 2
STM32_Programmer_CLI -c port=SWD mode=UR freq=1000 -d keil5_g431\Objects\gimbal_g431_node2.hex -v -rst
# 3) 等约 25 s（4 行 × 2 次拉轴），取符号地址后 dump 128 字节
arm-none-eabi-nm Objects\gimbal_g431.axf | findstr bench_align_result
STM32_Programmer_CLI -c port=SWD mode=HOTPLUG freq=1000 -r32 0x20000280 128 > align_raw.txt
# 4) 拟合
python tools\g431_fit_align.py align_raw.txt
# 5) 把输出的 zero/dir 写进 User/calib.h 对应 BOARD_CAN_NODE 分支，宏改回 0，重烧
```

`bench_align_result[]` 每行 8 个 float：`[0]` 起始机械角、`[1]` 上行拉轴稳定角、
`[2]` delta、`[3]` 最大电流、`[4]` 结果码、`[5]` nFAULT、`[6]` 下行拉轴稳定角、
`[7]` 指令电角度。

## 板 1 复核（`zero=1.227 / dir=−1`，交付固件）

板 1 原用 2026-10-27 单次拉轴值 `zero=1.697`，闭环误差 0.08°，一直能跑。用双向拉轴重测：

```
row0 up=5.03911 down=5.02452   row1 up=5.03786 down=5.02420
row2 up=4.88745 down=4.87359   row3 up=4.75073 down=4.73947

pp=11  dir=-1  zero=1.227 rad   rms 4.7°  max 8.1°（上下行磁滞 6–8°）
```

与旧值差 0.47 rad = **27° 电角**，正是单次拉轴的摩擦偏置量级（板 2 两次单次拉轴差 16°、
板 3 差 4.5°）。结论：**单次拉轴只能当粗测，交付值必须用双向拉轴**。

| 项目 | 结果 |

| 匀速 1.5 rad/s 抖动 | speed −1.4998、`jitter_std 8.96 mrad` |
| 匀速 9 rad/s 抖动 | speed −8.9999、`jitter_std 13.21 mrad` |

板 1 的选项字节实测已是 `nSWBOOT0=0 / nBOOT0=1`（不会被 PB8 拖进 bootloader），无需再改。

## 三块板同总线联调（2026-10-28）

三块板同时上电、同一条 CAN 总线（candleLight，500 kbit/s），各自 `--node N`：

| 检查 | 结果 |
|---|---|
| 三块板同时应答 | node1 `dir=−1 zero=1.227`、node2 `dir=−1 zero=0.122`、node3 `dir=+1 zero=0.487`，全部 `Vbus=24.0 nFAULT=1` |
| 同时下发不同目标（+0.5 / −0.5 / +0.5 rad） | 三块各自到位，误差 **0.006° / 0.000° / 0.092°** |
| 只命令 node2（+0.5 rad） | node1 漂移 **0.0000 rad**，node3 0.0046 rad（自身位置环回 settle，非串扰） |
| 广播帧 `0x200` | 三块都收、都不回（`REPLY_ID=-1`） |

结论：节点寻址可用，三块板可挂同一条总线独立控制。

## 上电后排障：AS5600 一次都不应答

板 3 上电后出现过"`sensor_errors` 每周期 +1、`cs_amp_mid≈−7 A`、`nFAULT` 低、`EN` 被拒"
的组合。原因不是硬件坏，而是 **AS5600 卡在总线上不应答**：`as5600_update()` 读失败时
会主动 `board_driver_set(0)` 关驱动，于是 CSA 没偏置、nFAULT 被拉低，看起来像功率级故障。
**处理办法：把板子的 5V/24V/ST-Link 全部断电 5 秒再上电**，传感器释放总线后立刻恢复
（实测上电后 `angle` 正常、阶跃 0.011°）。

判据：上电后 `sensor_errors` 一直涨 + `sensor_valid=0` → 先断电重启，别查功率级。

## 注意事项

- 磁铁环是手工粘的，零点拟合残差 5° 量级是**传感器安装非线性**，不是算法问题；
  追求更高精度需要做整圈角度线性化表，对云台用途没有必要。
- **换电机必须重标**：`zero` 与 `dir` 是"板 + 电机 + 磁铁环 + 相线顺序"的组合属性。
  板 1/2/3 现在装的都是各自的电机，标定与实物对应。
- 三块板的选项字节都已确认是 `nSWBOOT0=0 / nBOOT0=1`（PB8 被 CAN 收发器拉高也不会进
  bootloader）；新板首次烧录仍建议顺手读一遍 `-ob displ` 确认。
