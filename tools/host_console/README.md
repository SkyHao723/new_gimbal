# 上位机板 有线串口控制台（Web Serial）

一个单文件的网页控制台，浏览器直接和上位机板的 CH343P 串口通信——**不需要任何后台服务/桥**。
用 Chrome / Edge 的 Web Serial API 打开 COM 口，收发文本命令，并把状态解析成卡片。

## 用来做什么

- 有线控制三块驱动板：使能/失能、目标角、电压上限、速度上限、运动模式（M0 缓动 / M1 直驱）
- 看板级状态：SYSCLK、CAN PSR/ECR、串口丢字节、IMU 地址、命令计数
- 读 IMU：加速度 / 角速度 / 温度
- 一键广播巡检（`n`）或逐板查询（`c1 ?`）

## 怎么打开

前提：上位机板已烧 `host_bringup.hex`，CH343P 的 USB 插到电脑（设备管理器里出现 `USB-Enhanced-SERIAL CH343 (COMx)`）。

1. 用 **Chrome 或 Edge**（Firefox / Safari 不支持 Web Serial）打开本目录的 `index.html`
   - 直接双击打开（`file://`）通常可以；
   - 若浏览器不给权限，用本地静态服务：
     ```powershell
     cd <仓库>\tools\host_console
     python -m http.server 8770
     ```
     然后访问 http://127.0.0.1:8770/
2. 点右上 **连接串口**，在弹出的列表里选 CH343 那个 COM 口（波特率保持 115200）。
3. 连接后会自动发一条 `b` 取板级状态，终端里看到回显与回复即成功。

> 串口是独占的：Arduino IDE 的串口监视器、`host_cmd.py`、`host_bringup_check.py`
> 之类的程序会占着 COM 口，用网页前先关掉它们（否则浏览器报 `Failed to open serial port`）。

## 界面

| 区域 | 说明 |
| --- | --- |
| 终端 | 收发的原始文本；本机发出的命令以 `»` 显示，回显会被自动去重 |
| 一键操作 | `h` `b` `m` `n` `l`，以及 1/2/3 号板状态、全部状态 |
| 下发指令 | 选节点 + 选操作（T/V/L/M）+ 数值 → 自动拼成 `c<N> <op><value>` 发出 |
| 快捷按钮 | 全部使能/失能、M0/M1、V2.5/V4/V8 |
| 相对移动 | 先 `c<N> R` 读当前角，再发 `T(当前角 ± Δ)`；Δ 单位 rad |
| 板级状态 | 由 `b` 的回复解析：时钟、CAN PSR/ECR、UART1 丢字节、IMU 地址、命令数 |
| IMU | 由 `m` 的回复解析：acc / gyro / temp |
| 驱动板卡片 | 由 `c<N> ?` 或 `n` 的回复解析：使能状态、角度、目标、误差（°）、电压上限、相电流 pk |

底部勾选「每 2 秒自动刷新三块板」会轮流发 `c1 ? / c2 ? / c3 ?`。

## 命令格式（与固件一致）

上位机板命令：

```
h 或 ?        帮助
b             板级状态
m             读 IMU
t             IMU 压力测试
i             I2C 重扫
n             广播巡检三块驱动板
l             翻灯
c<N> <cmd>    转发给驱动板 N（N=0 广播），例如 c1 T0.5  c1 M1  c2 ?  c0 V2.5
```

驱动板命令（`c<N>` 后面那段由驱动板解析）：`E` 使能、`D` 失能、`T<rad>` 目标、`V<volt>` 电压上限、
`L<rad/s>` 速度上限、`M<0|1>` 缓动/直驱、`?` 状态、`R` 编码器、`H` 帮助。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 点连接没有串口可选 | 换 Chrome/Edge；确认 CH343 驱动已装、设备管理器里没有黄色感叹号 |
| `Failed to open serial port` | 别的程序占着 COM 口（Arduino 监视器 / python 脚本），先关掉 |
| 终端有回显但没回复 | 板子可能刚复位；再发一次 `b`；确认波特率 115200 |
| 驱动板卡片一直是「—」 | 驱动板没上电或 CAN 没接，`n` 看是否有回包；卡片数据来自 `c<N> ?` |
| 相对移动报「没读到当前角度」 | 该节点不在线，先用 `c<N> ?` 确认 |
| 页面刷新后要重连 | Web Serial 不会自动重连，属正常现象 |

## 备注

- 本页只做「有线（USB 串口）」这条链路；以后 ESP32 无线控制会另做一套（走 WebSocket 桥）。
- 固件侧的行编辑（退格、Ctrl-U、Ctrl-C、方向键吞掉）在网页里同样有效，
  网页输入框自己也有 ↑↓ 命令历史。

## 自测（不需要浏览器和硬件）

页面里「串口回包 → 状态卡片」的解析逻辑有一个不依赖硬件的自测，喂的是真实固件回包文本：

```powershell
cd <仓库>\tools\host_console
node test_parser.js
```

输出全部 `PASS` + `ALL PAGE CHECKS PASSED` 即通过；它还会检查脚本里 `$("id")` 引用的元素在 HTML 里是否存在、有没有重复 id。
（改页面 JS 后建议先跑一遍，比在浏览器里点快得多。）
